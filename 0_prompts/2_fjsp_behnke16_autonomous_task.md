The task is to design a heuristic for a flexible job-shop benchmark taken from the literature. The instance comes from the benchmark family of Behnke and Geiger (2012) and is stored in [INSTANCE FILE]. The best upper bound known so far is 412, and we want to beat it, so your schedule needs a makespan of 411 or less.

The instance is in FJSPLIB format. Line one gives `<jobs> <machines> <average eligible machines per operation>`. Every following line describes one job: first its number of operations, then for each operation the count of eligible machines and that many `<machine> <duration>` pairs. Machine numbering starts at 1. The operations of a job must run in the order listed. Each one occupies exactly one of its eligible machines for the duration given for that machine. A machine processes one operation at a time, and operations cannot be interrupted. The makespan is the time at which the last operation ends, and minimising it is the objective.

Put your solver code and any other files you create inside [SOLUTION DIRECTORY]. Only the outcome is evaluated: save your best schedule to [SCHEDULE FILE]. A small sample instance together with a sample schedule is in [EXAMPLE DIRECTORY], showing the required format. The file starts with a `makespan <value>` header, followed by one row per operation as `<job> <operation> <machine> <start> <end>`. Jobs and operations count from 0, and machines count from 1 as in the instance file. Overwrite the schedule file every time you find something better instead of waiting until the end. The makespan is recomputed from your rows, so the header value must match what the schedule really achieves.
